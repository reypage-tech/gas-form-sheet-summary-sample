# フォーム回答シート集計（Google Apps Script 見本）

> 見本データのみを用いています。デモ画像は実際の Google アカウントの画面ではなく、再現した静止画です。

## 課題
国内向けの申込・アンケート・社内申請を Google フォームで受け付けると、回答はスプレッドシートに溜まる一方で、受付番号の付与、担当の割当、期限の管理、未対応の可視化、新着や期限切れの共有は別作業になりがちです。表計算だけでは状態の更新や通知まで一続きにしにくい場面があります。

## しくみ
1. **フォーム送信トリガー（onFormSubmit）** が回答行を読み、**設定** シートの種別に応じて **受付番号**（例 `R-2026-0001`）、**状態**（未対応）、**担当**、**期限**（受付日から種別の日数を進め、土日は進めない）を書き込みます。
2. カスタムメニュー **申込集計 > 一覧を作り直す** で **一覧** タブを組み直します。並び順は状態、担当、期限です。期限を過ぎて未完了の行には **※** を付けます。**未付与行を一括補完** で、受付番号が空の既存行にも同じ付与処理を一括適用できます。
3. 新着は送信直後に、期限切れはメニュー **期限切れの通知を送る** または時間主導トリガーから、メール（スクリプトプロパティ `NOTIFY_EMAIL`）と Google Chat  Incoming Webhook（`CHAT_WEBHOOK_URL`）へ送ります。Webhook URL が空のときは Chat へは送りません。テスト用に `DRY_RUN` を `1` にすると送信せず `console.log` のみです。Chat POST では `muteHttpExceptions: true` とし、応答コードを `console.log` に残します（200 以外でも例外にしません）。受付番号の採番（`nextReceiptNumber_`）は `LockService.getScriptLock()` の `waitLock` / `releaseLock`（`finally`）で排他します。

## ルール
- **状態**: 未対応 / 対応中 / 完了（初期値は未対応。対応中・完了はシート上で手入力想定）
- **受付番号**: `R-年-連番`（連番は 0001 から。年が変わると 0001 に戻る）。**年**は回答のタイムスタンプではなく、採番処理を行った日（スクリプト上の「本日」）の暦年です
- **種別と設定**: 回答の種別が **設定** シートに無い場合は、ひな型の `__default` と同様に **期限 5 日・担当空欄** で付与します。種別の追加漏れに気づきにくいので、新しい種別をフォームに足したら設定行も追加してください
- **期限**: 受付日を起点に、設定の「期限日数」を満たすまで日付を進める。土曜・日曜は進めない
- **一覧の並び**: 状態（未対応、対応中、完了の順）、担当（文字列順）、期限（早い順）
- **期限切れ**: 状態が完了以外で、期限日が本日より前
- **通知**: 件名に `[申込集計]`。本文は受付番号・種別・件名・担当・期限・状態の1行形式

## 設定
1. Google フォームを作成し、回答先スプレッドシートを用意します。回答タブ名が **フォームの回答 1** である想定です（Apps Script 内 `SHEETS.RESPONSES` で変更可）。
2. `sample_data/settings.csv` を **設定** タブ、`sample_data/responses.csv` を回答タブの参考として取り込むか、テスト用にコピーします。
3. 拡張機能 > Apps Script に `src/Code.gs` を貼り、マニフェストを `src/appsscript.json` に合わせます（clasp 利用可）。
4. トリガーで **フォーム送信時** に `onFormSubmit` を追加します。
5. スクリプトプロパティ（任意）: `NOTIFY_EMAIL`、`CHAT_WEBHOOK_URL`、`DRY_RUN`（`1` でログのみ）
6. 期限切れ通知を自動化する例（Apps Script エディタで一度実行するか、トリガー画面から同等の時間主導トリガーを追加）:

```javascript
ScriptApp.newTrigger('notifyOverdue').timeBased().atHour(9).everyDays(1).create();
```

   上記のように `ScriptApp.newTrigger` で時間主導トリガーをコードから作成する場合は、OAuth スコープ `https://www.googleapis.com/auth/script.scriptapp` が必要です（本見本の `src/appsscript.json` に含めています）。エディタのトリガー画面だけで追加する場合は、通常そのスコープは不要です。

見本 CSV 20 行を `tests/local_check.js` で処理した結果: 受付付与 20 件、一覧 20 行（固定の「本日」2026-10-20 で期限切れ ※ は 15 件）。Node のスタブで SpreadsheetApp / MailApp / UrlFetchApp / LockService を置き換え、`src/Code.gs` をそのまま実行して件数を assert しています（年またぎの受付番号リセット、採番時のロック取得・解放、Chat 応答コードのログも同ファイルで確認）。

## ファイル
- `src/Code.gs`, `src/appsscript.json`: スクリプト本体
- `sample_data/responses.csv`, `sample_data/settings.csv`: 架空の会社・氏名の見本データ
- `tests/local_check.js`: Node 上のロジック確認（Google アカウント不要）
- `demo/frame_*.png`: 再現画面（`demo/make_demo.py` で生成）

## 制約
- フォーム項目名（タイムスタンプ、種別、件名など）は見本 CSV に合わせています。項目を変えた場合は `COL` 定数と CSV を揃えてください。
- 回答タブに受付番号・状態・担当・期限の列が無い（フォームの質問列だけの）状態でも、行単位の付与処理と **未付与行を一括補完** は先頭行へ管理列を追加してから書き込みます。手で列を用意する必要はありません。
- Chat Webhook は URL をプロパティに置いた場合のみ POST します。メールも `NOTIFY_EMAIL` がある場合のみ送ります。
- 大量行のパフォーマンスは未検証です。
- **一覧** タブは **一覧を作り直す** のたびに内容を組み直して上書きします。シート上のフィルタや列幅などの表示設定は残りません。
